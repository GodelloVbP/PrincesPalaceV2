Shop Screen — v2

Prince’s Palace v2
Prepared 3 September 2026

This note hands off the interactive shop prototype for independent review. It covers what the screen does, what changed from the original written handoff, open decisions that need a call, and where the working files live. The prototype itself is the source of truth for layout and behavior — this document explains it, not the reverse.

What it is

A single shop room: browse spell books, gear, and relics; hover a row for its tooltip; click once to arm a purchase, click again to confirm. A separate Pack button opens the player’s bag to sell items. Reroll replaces all offers at a doubling price with a hard ceiling. A demo-only debug panel forces sold-out, no-offer, and price-ceiling states for testing.

Default state — relics, spell books and shopkeeper art on top; a 2×2 gear grid and the shop actions panel below.

Pack modal — sell flow: arm a row, then sell one or the full stack.

Demo controls panel, forcing a relic into the NO OFFER state.

Deviations from the written handoff

  • Pack button opens a dedicated modal for selling — it replaced the inline “sell from bag” panel in the original row layout. It is the only thing Pack opens; there is no separate inventory surface elsewhere on this screen.
  • Spell-slot assignment is out of scope here. Buying a spell book now behaves like buying gear or a relic (arm → confirm → sold); assigning a learned book to a character happens in the character screen.
  • Layout is a fixed, non-scrolling 5-panel grid — relics / spell books / shopkeeper art across the top, a 2×2 gear grid and a shop-actions panel below — matching the reviewed sketch rather than the horizontal-rows layout in the original spec.
  • Hover tooltips replaced the persistent detail panel. Every buyable row shows name, kicker and effect on hover instead of a fixed "select a card" side panel.
  • Icons and the shopkeeper portrait are drag-and-drop placeholders — no art pipeline is wired in yet.

Unchanged from the original spec: reroll price doubling with a ceiling, the afford / unaffordable / sold / no-offer states, gold token coloring, the two-press Leave confirm, and Escape-to-cancel behavior.

Open questions for this review

Two decisions are still open and would benefit from an outside read before art and audio pass begins:

  1. Empty-state entry. NO OFFER and SOLD currently only appear via the debug panel. Should either ever occur through normal roll logic (e.g. a relic genuinely has no offer this visit), or should both stay demo-only until a later systems pass?
  2. Sell-price formula. Bag items currently sell at a hardcoded 30%-of-cost value baked into each bag entry. Should sell price instead auto-derive from each item’s cost at sell time, so it stays correct if item costs change later?

Secondary, lower-priority items: a visible keyboard focus ring on rows (currently tab-focusable but unstyled), and a confirm-pulse animation on the arm→confirm transition.
