# Bug hunt, 2026-09-10

Four Opus hunters against four slices of the tree, in the shape
`docs/BUG_HUNT_2026-09-08.md` records: combat and the resource-pool model; the run
outside combat; the fight stage and its presentation; verification/content tooling
plus the UiKit layer. One integrator gated all of it into `prismatic-orb`.

The day's work was not only the hunt. It opened with the pool model's phases C and E
(`cd265cd2`, `1a6b20b9`, `9f599f06`) — spell books becoming a pool's decision, Bjorn
trading mana for a Fury bar, and the primary pool's per-action gains moving onto the
damage funnel — and with the PC-plate pass (`fd6314c1`, `84fc988f`), which replaced
"the acting character on a big card plus a roster of small ones" with three identical
per-character plates. Several of the hunt's findings are the seams those two passes
left behind, which is the ordinary shape of a hunt run on the same day as the work.

## (a) Method

Same as 2026-09-08, and it is worth restating because it is what makes the findings
checkable: each hunter read its slice **adversarially rather than for style** — pick a
stated contract (a comment, a test name, a doc line) and try to make it lie. Where one
did, the hunter wrote the failing test FIRST, against the contract, before touching
the fix, then fixed the mechanism the test named rather than the symptom it happened
to catch. One commit per bug, so `git log` reads as a list of what was wrong.

Two things differed from the 2026-09-08 wave, both worth keeping:

- **The hunters reported rather than fixed.** Each wrote a ranked report to the
  scratchpad — `hunt/{combat,run,stage,tools}.md` — with, per finding: the file and
  line, the contract quoted **verbatim**, a repro, the failing test to write with its
  literal expected value, the proposed fix, and a confidence label. Four fixers then
  worked from those reports. The split is what let a finding be graded before anyone
  spent a commit on it, and it is why the "Owner's calls" table below is populated
  from the same pass rather than discovered afterwards.
- **Confidence was graded and the grades held up.** The combat hunter labelled five
  findings *Confirmed by a run* — a scratch NUnit project referencing
  `tools/domain-tests/PrincesPalace.Domain.csproj`, nothing in the repo written to —
  against *High* (code read) and *Plausible* (latent, unreachable with today's
  content). Every *Confirmed* finding produced a failing test on the first try. Two
  *Plausible* ones (#10 lock keying, #8 map cache) turned out to be one line of future
  wiring away from live, which is exactly what that label is meant to mean.

A consequence of the split worth internalising: **a report is not a fix, and a report
that names its own test is nearly one.** The findings that cost a fixer the least were
the ones whose report carried the literal — "today it reads `0`", "today the meta is
`CONSUMABLE · MANA` and `CanPay` is true".

suggested. Five settings were captured and measured to find the balance point, and the
